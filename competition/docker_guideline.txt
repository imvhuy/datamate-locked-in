1. Overview 
Submit one Docker image containing the complete inference solution, training code/data and 
verification artifacts. Inference must work offline. Only open-source training-only base 
checkpoints may use public links. 
Submit and freeze your image before private test release. Then run it and upload 
submission.jsonl for the provisional leaderboard. The organizers’ re-run determines your 
final score and ranking (Rule 8). 
The image must contain: 
Item Notes 
Inference code Code and dependencies to read /data and write /result, fully offline. 
Training code Training/fine-tuning source, configs, dependencies, logs and run instructions (section 8). 
Training data pipeline 
Generation/preprocessing code, training/validation data, logs, 
verification checkpoints and a manifest of local paths and checksums 
(section 8). 
Model weights All weights, tokenizers and configs needed for inference, including both base model and adapter when used. 
predict.sh Entry point: /data → /result/submission.jsonl and /result/logs/. 
README.md Approach, model declarations, and run instructions (section 8). 
2. Test machine 
Item Value 
GPU 2 × NVIDIA RTX 5090, 32 GB VRAM each (64 GB total) 
RAM 512 GB 
CUDA CUDA ≥12.8; matching PyTorch/vLLM build with Blackwell support. 
Base image 
Recommended: vllm/vllm-openai:v0.10.1.1 (tested with PyTorch 
2.7.1+cu128 and vLLM 0.10.1.1). Alternatives must support RTX 
5090 / compute capability 12.0. 
Network Disabled during inference: no APIs or downloads. 
/data Read-only. Write temporary files elsewhere, e.g. /tmp. 
Time limit 6 hours for the complete private test set, including model loading (Rule 7). 
Models 
All inference models combined: ≤15B parameters, including every 
MoE parameter, even if loaded separately. Includes language, 
embedding, reranking, and classification models. Quantization 
allowed (Rule 2).

3. Input and output 
3.1. /data 
Each test split contains the business files, questions, and shared rulebook/calendar shown 
below. 
/data/ 
├── data/<business_id>/ 
│   ├── *.csv | *.xlsx | *.sqlite 
│   └── README.md 
├── rulebook.md              # split-specific rules and vocabulary 
├── calendar.csv             # shared solar–lunar calendar 
└── questions.jsonl          # id, business_id, question, as_of_date 
3.2. /result/submission.jsonl 
One JSON object per line: id, type and answer for value types (number, percent, string, date, 
boolean, list, table). unanswerable may include reason; abstain needs no answer. Missing 
questions count as abstain. 
Write an answer immediately. If the run stops early or exceeds 6 hours, only saved answers 
are scored; the rest count as abstain. 
3.3. /result/logs/ 
Write one log record per question under /result/logs/. Any format is accepted. Required 
fields: 
• id: question ID. 
• answer: final answer. 
• elapsed_ms: non-negative integer wall-clock milliseconds from question start to final 
answer, including data reads, reasoning and code execution. With batching, measure 
from when the question enters its batch. Shared model loading is separate but 
counts toward 6 hours. 
• thinking: the model’s reasoning for this question, recorded as generated (e.g., the 
text inside <think>…</think> or vLLM’s reasoning_content). Do not summarize or 
truncate it. If several model calls were made for the question, record a list of strings 
in call order. Use null if no reasoning was generated (e.g., thinking mode disabled or 
no model call). 
For questions solved by code, also record: 
• code: the actual generated code that was executed. For predefined Python, record 
the source file/function and actual inputs. Generated code may call packaged helper 
functions; log the actual call. 
• output: the computed return value or execution output. Printing to stdout is not 
required. 
If no code is executed, code and output may be omitted or null. Code generation is optional; 
logs must reflect the actual computation.

inside the Docker image; output may be a returned value without stdout. 
4. Folder layout in the image 
Suggested internal layout. /code/predict.sh and the section 3 input/output paths are fixed. 
Document other folder locations in /code/README.md. 
/code/ 
├── predict.sh               # entry point 
├── README.md 
├── requirements.txt 
├── src/                     # inference code 
├── models/                  # model weights 
└── training_code/ 
    ├── README.md 
    ├── requirements.txt     # pinned training dependencies 
    ├── train.sh             # training entry point, if trained 
    ├── configs/             # training and generation settings 
    ├── src/                 # training source code, if trained 
    ├── data_generation/     # generation and preprocessing scripts 
    ├── data/                # train/validation data 
    ├── logs/                # training logs 
    ├── checkpoints/         # verification checkpoints, if needed 
    └── data_manifest.json   # local paths, SHA-256; base model public URLs

Package all training data, code, dependencies and verification evidence. Only open-source 
training-only base checkpoints may be linked (section 8). Remove redundant files; retain 
optimizer state only if verification needs it. 
For inference, include both the base model and adapter, or a merged checkpoint. A public 
base-model link does not replace required inference weights. 
5. predict.sh rules 
1. Run bash /code/predict.sh without arguments. 
2. Read /data; write submission.jsonl and per-question logs under /result. Create 
missing output directories. 
3. Set fixed defaults for model, seed, temperature, batch size, and other settings. The 
organizers will not modify them. 
4. No manual intervention, hard-coded answers or logic keyed on question/business 
IDs. 
5. Agents may generate and execute code inside the container (optional; Rule 5). 
6. Reproducibility 
Reproducibility requires |PA(uploaded) − PA(re-run)| ≤ 0.03. Use fixed seeds or greedy 
decoding. The re-run score is final (Rule 8). 
Case What happens 
|PA(uploaded) − PA(re-run)| ≤ 
0.03 The re-run score is your final score. 
Difference > 0.03 The organizers review the logs and may re-run the image or ask your team for more information. 
Difference cannot be explained The entry is disqualified. 
 
GPU batching may change outputs between runs, even with greedy decoding. Before you 
submit, run your image twice on the same input and compare the two submission.jsonl files, 
or compute PA on the training set (it has answers.jsonl). Rule 8 compares your uploaded 
private-test PA with the organizers’ re-run. 
7. Run time 
• Process the complete private test within 6 wall-clock hours on the reference machine, 
including loading and initialization. 
• Reference only: Qwen3-14B initialization took about 2 minutes (128,155 ms), 
including compilation and CUDA graphs. 
• At the time limit, the organizers stop the container; unsaved answers count as 
abstain. 
• Tie-breaks: lower total inference time in the organizers’ re-run, then earlier 
submission.

8. README and training code 
/code/README.md must include: 
• Approach: reading data, generating/executing code, and choosing answers. 
• Models: name, public source, fixed revision, original release date, license, and 
parameter count. Original weights must predate 26 October 2026 with a license 
permitting use. Fine-tuning is allowed; apply the 15B total in section 2. 
• Data: sources/versions, generation/preprocessing method and train/validation 
sample counts. 
• Allowed: provided training data, self-generated data and public datasets/models. 
Never train on public/private test data or collect test answers (Rule 6). 
/code/training_code/ must support verification and reproduction. Include: 
• Code/environment: training and data-generation/preprocessing source, configs, 
prompts/templates, pinned dependencies and seeds. Install dependencies or bundle 
an offline environment. 
• Data/evidence: all train/validation data, logs, run configs and verification checkpoints 
inside the image. Save prompts/responses for API-generated or non-reproducible 
data. 
• README: exact preparation/training/export commands, hardware, runtime, 
generator model/settings, final checkpoint/adapter and any nondeterministic steps. 
• data_manifest.json: local paths, sources/versions, file sizes, SHA-256 checksums 
and dataset counts/splits. 
For omitted open-source training-only base checkpoints, provide public URLs, fixed 
revisions, licenses, required files and SHA-256 checksums. All inference assets stay inside 
the image. 
The organizers may reproduce preparation/training separately from the 6-hour inference 
limit. State explicitly if no training or data generation was performed. 
9. Build the image 
Build for linux/amd64 with all required inference/training assets. Make sure .dockerignore 
does not exclude training data. Exclude only unused files and build caches. 
Sample stack: Docker 24.0.5 with BuildKit. 
1. Install Docker/BuildKit and NVIDIA Container Toolkit. RTX 5090 requires a 
compatible R570-or-newer driver; follow the official guides below. 
Docker: https://docs.docker.com/engine/install/ 
NVIDIA Container Toolkit: https://docs.nvidia.com/datacenter/cloud-native/container-
toolkit/latest/install-guide.html 
2. Pull the base image: docker pull vllm/vllm-openai:v0.10.1.1

3. Copy code, inference weights, training data and verification materials into /code. 
Include dependencies and the artifact manifest. 
4. Install libraries in the Dockerfile. For the recommended two-GPU stack: 
• Reset ENTRYPOINT [] so that a plain docker run starts predict.sh, not the vLLM 
server. The scoring command also sets --entrypoint bash (section 10). 
• The sample fixed a two-GPU initialization hang by upgrading NCCL 2.26.2 to 
nvidia-nccl-cu12==2.27.7. Validate this workaround with your stack. 
• The tested GPU pair lacked P2P access; the sample sets 
NCCL_P2P_DISABLE=1. vLLM disables custom all-reduce when P2P is 
unavailable. 
• Set HF_HUB_OFFLINE=1 and TRANSFORMERS_OFFLINE=1; load packaged 
local models. 
5. Build and inspect the image. Use zaic2026_datamate_<team_name>:final, 
replacing <team_name> with a lowercase team identifier. 
docker build --platform linux/amd64 \ 
  -t zaic2026_datamate_<team_name>:final . 
docker image inspect \ 
  -f '{{.Os}}/{{.Architecture}} {{.Size}}' \ 
  zaic2026_datamate_<team_name>:final 
docker run --rm --network none --entrypoint "" \ 
  zaic2026_datamate_<team_name>:final find /code -maxdepth 2

FROM vllm/vllm-openai:v0.10.1.1

ENV HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \ 
    PIP_NO_CACHE_DIR=1 NCCL_P2P_DISABLE=1 
WORKDIR /code 
COPY requirements.txt /code/requirements.txt 
RUN pip install --no-cache-dir -r /code/requirements.txt 
RUN pip install --no-cache-dir --no-deps nvidia-nccl-cu12==2.27.7 
COPY models/ /code/models/ 
COPY training_code/ /code/training_code/ 
COPY predict.sh README.md /code/ 
COPY src/ /code/src/ 
RUN chmod +x /code/predict.sh 
CMD ["bash", "/code/predict.sh"] 
Install training dependencies or bundle an offline training environment under training_code/. 
Test the finished image with section 10’s command. 
Disk planning: the sample used about 57 GB for image/build cache and another 50 GB 
temporarily during export on Docker 24. Actual needs vary; also allow space for training data 
and the archive. 
10. Check before you submit 
Test with the scoring command: two GPUs, no network, read-only input, and 16 GiB shared 
memory. 
The organizers provide no privileged mode, Docker socket, host credentials, or host 
services. 
docker run --rm --gpus '"device=0,1"' --network none --shm-size=16g \ 
  --entrypoint bash \ 
  -v /path/to/public_test:/data:ro \ 
  -v /path/to/output:/result \ 
  zaic2026_datamate_<team_name>:final /code/predict.sh 
The sample exceeded the default 64 MiB /dev/shm during NCCL allocation. --shm-size=16g 
resolved that capacity issue without host IPC. The scoring command sets --entrypoint bash, 
so the image's own ENTRYPOINT is not used.

Check that: 
• It runs to the end with no errors and no network. 
• submission.jsonl covers every question in the published format. 
• Each question has a log record with id, answer, elapsed_ms and thinking (null if no 
reasoning was generated). 
• Estimated private-test time fits within 6 hours: model loading + (average time per 
question on a public or training run × 500). 
• Two runs give the same answers, or their PA on the training set differs by at most 
0.03 (section 6). 
• Inference works offline; all training data, code, and verification evidence are 
packaged. 
• Export one linux/amd64 image/tag; its uncompressed .tar size is at most 100 GB 
(section 2). 
11. Submit the image 
1. Export only the final linux/amd64 image/tag and compress it for upload. Run in Bash 
and replace <team_name> with your lowercase team identifier. Run set -o pipefail 
first: without it, a failed docker save still leaves a small .tar.gz and the command 
reports success. Then measure the uncompressed .tar size from the archive:

set -o pipefail 
docker save zaic2026_datamate_<team_name>:final | gzip > 
zaic2026_datamate_<team_name>.tar.gz 
# uncompressed .tar size in bytes: 
gzip -dc zaic2026_datamate_<team_name>.tar.gz | wc -c 
Model weights compress poorly: the sample image went from 50.6 GB as .tar to 34.4 GB as 
.tar.gz. pigz -p 8 (and pigz -dc) is much faster than gzip and produces a standard .tar.gz. 
2. On the build machine, before uploading, write the MD5 checksum of the .tar.gz to a 
file (on macOS, use md5 -r instead of md5sum): 
md5sum zaic2026_datamate_<team_name>.tar.gz > zaic2026_datamate_<team_name>.tar.gz.md5 
 
 
Figure 6. On the build machine: the uncompressed .tar size and the MD5 file sent with the upload. On a machine 
that downloaded the archive: md5sum -c compares that copy with the MD5 from the build machine. 
3. Upload the .tar.gz and send its link, the .md5 file (or its one line) and the 
uncompressed .tar size in bytes to the organizers. The organizers check their copy 
with md5sum -c zaic2026_datamate_<team_name>.tar.gz.md5: OK means the 
archive arrived intact, FAILED means it must be uploaded again.  
4. Do not rename the archive after creating the .md5 file. Before sending, download the 
archive from your link on another machine and run the same check, so you know the 
link works, and the file is intact.  
5. The artifact manifest must be inside the image; any external model reference is 
limited to an eligible open-source training-only base checkpoint.  
After the solution deadline, you may not change the image, code, configs, models, training 
data, generation artifacts or the declared public base-checkpoint revisions and checksums.
